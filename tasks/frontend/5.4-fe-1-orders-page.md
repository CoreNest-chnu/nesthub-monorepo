# Build /admin/orders list with status filter

**Complexity**: M | **Areas**: web | **US**: 5.4 — Order management | **Estimate**: 3h

## Context

Admin operations team needs a single screen to see all orders and their state. Pairs with `backend/5.4-be-1-orders-endpoints.md`. Status change UX is implemented in `5.4-fe-2-orders-status-change.md`.

## Granularity note

Frontend-only, list-view portion of US 5.4. Split from the mutation interactions so the read-only list can land first.

## Scope

**In**:
- New route `apps/web/src/app/admin/orders/page.tsx`
- shadcn `Tabs` filter with values matching `OrderStatus` (`all | pending | paid | shipped | completed | cancelled`)
- shadcn `Table` of orders showing: id (short), date (`createdAt`, formatted), customer (`firstName lastName`), items count, total amount, status badge
- Status rendered as a colored `Badge` (variant per status)
- Skeleton rows while loading; empty-state message when the filtered list has zero rows

**Out**:
- Order detail page
- Status-change interactions (covered in 5.4-fe-2)
- Pagination (out of scope unless the list is unmanageable; volume is small for MVP)

## Acceptance Criteria

- [ ] Page renders only for admins
- [ ] Switching tabs changes the active filter and the URL query (`?status=paid`) so the view is shareable/refreshable
- [ ] Date formatted consistently with other dates in the app (e.g., `dd.MM.yyyy HH:mm` — confirm the existing helper, do not invent a new format)
- [ ] Status badge colors are visually distinct (e.g., amber for `pending`, blue for `paid`, indigo for `shipped`, green for `completed`, red for `cancelled`)
- [ ] Loading and empty states are both implemented (not just blank rows)
- [ ] All copy in English

## Implementation Hints

- shadcn primitives needed — install if missing:
  ```bash
  cd apps/web && npx shadcn@latest add tabs table badge skeleton
  ```
- Hook: `useAdminOrdersControllerList({ status })` from `@repo/api-client`
- Read filter from URL: `useSearchParams()` + `useRouter().replace(...)` on tab change
- Reuse existing date formatter — search `apps/web/src` for `format(` / `formatDate` before adding a new util
- Badge variant map:
  ```ts
  const statusColor: Record<OrderStatus, string> = {
    pending: 'bg-amber-100 text-amber-900',
    paid: 'bg-blue-100 text-blue-900',
    shipped: 'bg-indigo-100 text-indigo-900',
    completed: 'bg-green-100 text-green-900',
    cancelled: 'bg-red-100 text-red-900',
  };
  ```
