# Wire edit-product form save flow

**Complexity**: S | **Areas**: web | **US**: 5.2 — Product editing | **Estimate**: 1h

## Context

Pairs with `5.2-fe-1-edit-product-form.md` and depends on `backend/5.2-be-1-update-product-endpoint.md`.

## Granularity note

Small frontend-only task — splits the API integration from the form scaffolding so each can be reviewed in isolation.

## Scope

**In**:
- Submit handler using `useAdminProductsControllerUpdate` (Orval-generated)
- Send only changed fields (`dirtyFields` from react-hook-form) — PATCH semantics
- Success path: invalidate the product detail query, `toast.success('Product updated')`, `router.push('/products/{id}')`
- Error path: surface `400` field errors / show error toast for other failures

**Out**:
- Optimistic updates

## Acceptance Criteria

- [ ] Submitting saves changes and redirects to `/products/{id}` where updated data is visible
- [ ] Only dirty fields are included in the PATCH payload (verify in network tab during review)
- [ ] Catalog listing (`/products`) and product detail page show the updated values without a hard refresh (relies on query invalidation)
- [ ] Validation errors from server map back to the appropriate field
- [ ] Submit disabled while pending; no duplicate submissions possible

## Implementation Hints

- Build the partial payload:
  ```ts
  const onSubmit = (values: ProductFormValues, dirtyFields: FieldNamesMarkedBoolean<ProductFormValues>) => {
    const patch = Object.fromEntries(
      Object.keys(dirtyFields).map(k => [k, values[k as keyof ProductFormValues]])
    );
    mutate({ id, data: patch });
  };
  ```
- Cache invalidation — call `queryClient.invalidateQueries({ queryKey: getGetProductsControllerFindOneQueryKey(id) })` (Orval exposes a `*QueryKey` helper next to each hook)
