# Build product edit form at /admin/products/:id/edit

**Complexity**: M | **Areas**: web | **US**: 5.2 — Product editing | **Estimate**: 3h

## Context

Reuses the `ProductForm` component from `5.1-fe-1-create-product-form.md`, prefilled with current product data. Submission/redirect handled in `5.2-fe-2-edit-product-submit.md`.

## Granularity note

Frontend-only by design — pairs with `backend/5.2-be-1-update-product-endpoint.md`. Split from submit logic for the same reason as 5.1.

## Scope

**In**:
- New route `apps/web/src/app/admin/products/[id]/edit/page.tsx`
- Fetch existing product via existing public hook (`useGetProductsControllerFindOne(id)` or equivalent)
- Prefill `ProductForm` via `defaultValues` / `reset()` once data loads
- Two buttons: **Save** (submits) and **Cancel** (`router.back()`)
- Loading skeleton while product data is fetching; 404 page if product not found

**Out**:
- API mutation wiring (covered in 5.2-fe-2)
- Deletion (no story for it in Epic 5)

## Acceptance Criteria

- [ ] Page renders only for admins (same middleware as 5.1-fe-1)
- [ ] Form fields are populated with the current product's values once the query resolves
- [ ] Unknown id → "Product not found" message + back link
- [ ] **Cancel** triggers `router.back()` without saving
- [ ] Validation rules identical to create form (zero / negative price rejected inline)
- [ ] Page is responsive at mobile/desktop breakpoints used elsewhere in admin

## Implementation Hints

- Extract `ProductForm` into `apps/web/src/components/admin/ProductForm.tsx` so both create and edit pages use it:
  ```tsx
  type Props = {
    defaultValues?: Partial<ProductFormValues>;
    isPending: boolean;
    onSubmit: (values: ProductFormValues) => void;
    submitLabel: string;
  };
  ```
- Use `useEffect` + `reset(data)` after the GET resolves, or pass `defaultValues` once `isLoading` is `false`
- Skeleton: shadcn `Skeleton` component — install if missing:
  ```bash
  cd apps/web && npx shadcn@latest add skeleton
  ```
