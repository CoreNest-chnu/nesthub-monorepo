# Wire create-product form to API with redirect

**Complexity**: S | **Areas**: web | **US**: 5.1 — Product creation | **Estimate**: 1h

## Context

Pairs with `5.1-fe-1-create-product-form.md` and depends on `backend/5.1-be-1-create-product-endpoint.md`. Once the form is built, this task hooks the submit handler to the auto-generated Orval mutation and handles success/error UX.

## Granularity note

Small frontend-only task split from the form scaffold so the form can be merged independently of the BE endpoint being ready.

## Scope

**In**:
- Submit handler using the Orval-generated mutation (expected name: `useAdminProductsControllerCreate`)
- Success path: `toast.success('Product created')` + `router.push('/products/{newProduct.id}')`
- Error path: `toast.error(message)` extracting message from the API error
- Form-level submission lock (no duplicate submits)

**Out**:
- Cache invalidation strategy beyond redirect (the destination page fetches fresh data anyway)

## Acceptance Criteria

- [ ] Submitting a valid form calls the API and, on `201`, redirects to `/products/{id}` and shows a success toast
- [ ] Submit button shows a spinner / disabled state while the mutation is pending
- [ ] Server validation errors (`400`) surface as either a toast or field-level errors mapped from the response body
- [ ] `403`/`401` responses redirect to login (consistent with rest of app)
- [ ] No request is fired if the form is invalid client-side
- [ ] After redirect, the new product is visible in the catalog `/products` listing

## Implementation Hints

- Import the mutation hook from `@repo/api-client`
- Toast usage pattern: `import { toast } from 'sonner'` (see `apps/web/src/app/providers.tsx`)
- Router: `import { useRouter } from 'next/navigation'`
- Disable button:
  ```tsx
  <Button type="submit" disabled={!isValid || isPending}>
    {isPending ? 'Saving…' : 'Create'}
  </Button>
  ```
