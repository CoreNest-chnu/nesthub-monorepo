# Create admin order endpoints with status transitions

**Complexity**: M | **Areas**: api | **US**: 5.4 — Order management | **Estimate**: 3h

## Context

Admins need to view all orders and progress them through their lifecycle. Status must only move forward (`PENDING → PAID → SHIPPED → COMPLETED`) — backward transitions or skips are invalid and would corrupt fulfillment state.

## Granularity note

Bundled as one backend task because the list and update endpoints share the same module, DTO surface, and authorization. Pairs with `frontend/5.4-fe-1-orders-page.md` and `frontend/5.4-fe-2-orders-status-change.md`.

## Scope

**In**:
- `GET /admin/orders?status=PENDING` — paginated-friendly list with embedded user info and item count
- `PATCH /admin/orders/:id` — `UpdateOrderStatusDto { status: OrderStatus }`
- Transition validation in service layer (reject backward / skipping moves with `400 BadRequestException`)
- Cancellation: `CANCELLED` is reachable from `PENDING` and `PAID` only (mirrors Prisma enum)

**Out**:
- Editing items / addresses / amounts
- Email notifications on status change
- Refund processing

## Acceptance Criteria

- [ ] `GET /admin/orders` returns array sorted `createdAt: desc`, each item containing `id`, `createdAt`, `status`, `totalAmount`, `user: { id, firstName, lastName, email }`, `itemsCount`
- [ ] `GET /admin/orders?status=PENDING` filters correctly; invalid status query → `400`
- [ ] `PATCH /admin/orders/:id` with valid forward transition → `200` with updated order
- [ ] Invalid transition (e.g., `PAID → PENDING`, `PENDING → COMPLETED`) → `400` with message naming both states
- [ ] Unknown id → `404`; non-admin → `403`
- [ ] Swagger documented so Orval generates `useAdminOrdersControllerList` and `useAdminOrdersControllerUpdateStatus`

## Implementation Hints

- Allowed transitions map:
  ```ts
  const ALLOWED: Record<OrderStatus, OrderStatus[]> = {
    pending:   ['paid', 'cancelled'],
    paid:      ['shipped', 'cancelled'],
    shipped:   ['completed'],
    completed: [],
    cancelled: [],
  };
  ```
- Prisma include for list response:
  ```ts
  this.prisma.order.findMany({
    where: status ? { status } : {},
    orderBy: { createdAt: 'desc' },
    include: {
      user: { select: { id: true, firstName: true, lastName: true, email: true } },
      _count: { select: { items: true } },
    },
  });
  ```
  Then map `_count.items → itemsCount` in a response model
- Use existing `OrderStatus` enum from `@prisma/client`
