# Create POST /admin/products endpoint

**Complexity**: S | **Areas**: api | **US**: 5.1 — Product creation | **Estimate**: 2h

## Context

Admins need a way to add new products to the catalog. The `apps/api/src/admin/` module already exists as an empty skeleton — you'll wire up the products controller inside it.

## Granularity note

This task is backend-only by design — it pairs with `frontend/5.1-fe-1-create-product-form.md` and `frontend/5.1-fe-2-create-product-submit.md` to form a single vertical slice. Depends on `5.1-be-2-roles-guard.md` (RolesGuard).

## Scope

**In**:
- `AdminProductsController` exposing `POST /admin/products`
- `CreateProductDto` with `class-validator` decorators
- `AdminProductsService.create()` using `PrismaService`
- Protect route with `JwtAuthGuard` + `RolesGuard` + `@Roles('admin')`
- Register controller/service in `AdminModule`

**Out**:
- PATCH / DELETE / GET endpoints (covered in other tasks)
- Image upload (only `imageUrl: string` is accepted)

## Acceptance Criteria

- [ ] `POST /admin/products` returns `201` with the created product when called by an authenticated admin
- [ ] Returns `403` for authenticated non-admin users
- [ ] Returns `401` for unauthenticated requests
- [ ] Validation rejects empty `name`, `price <= 0`, non-UUID `categoryId`, negative `stock`, with `400` and field-level messages
- [ ] Created row is visible in `GET /products` immediately
- [ ] Swagger doc updated (decorators on the controller); Orval regeneration produces a working `useAdminProductsControllerCreate` hook

## DTO shape

`apps/api/src/admin/dto/create-product.dto.ts`:

| Field | Validator | Required |
|-------|-----------|----------|
| `name` | `@IsString() @IsNotEmpty()` | yes |
| `description` | `@IsString() @IsOptional()` | no |
| `price` | `@IsNumber() @IsPositive()` | yes |
| `categoryId` | `@IsUUID()` | yes |
| `stock` | `@IsInt() @Min(0)` | yes |
| `imageUrl` | `@IsUrl() @IsOptional()` | no |

## Implementation Hints

- Mirror the structure of `apps/api/src/product/product.controller.ts` and `product.service.ts`
- Use the existing `AdminController`/`AdminService`/`AdminModule` skeleton at `apps/api/src/admin/` — either extend or create a sub-resource controller (`admin-products.controller.ts`) inside the same module
- Inject `PrismaService` and call `prisma.product.create({ data: dto })`
- Add `@ApiTags('admin-products')` and `@ApiBearerAuth()` so Swagger/Orval pick the route up
- Wire guards: `@UseGuards(JwtAuthGuard, RolesGuard) @Roles('admin')` at the controller level
